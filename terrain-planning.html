TERRAIN-AWARE PLANNING

Is the ground actually traversable?

The terrain-planning project turns a 2.5D elevation map into a graph that rejects unsupported, steep, rough, or discontinuous terrain before searching for a global route.

IMPLEMENTATION DETAILS

Terrain interpretation first. Search second.

Terrain Evaluation

FastDEM elevation cells are reconstructed as a regular terrain snapshot. Local surface geometry is evaluated before a node or edge is accepted.

  • 5 cm elevation lattice
  • PCA slope / roughness
  • Observed-support checks
  • Explicit adjacent-height step checks

Wavefront Roadmap + A*

A deterministic sampled roadmap expands around accepted nodes, validates candidate edges against terrain constraints, connects nearby valid nodes, and then searches the graph using a terrain-aware cost.

  • Ring-based proposals
  • Node merging / loop edges
  • Risk-aware A*

RRT* Comparison

A separate RRT* mode provides a sampling-based comparison under the same terrain evaluator and map contract.

  • Nearest → steer
  • Choose parent
  • Rewire
  • Deterministic seed option

Lifecycle & Revalidation

Changed height maps recheck the remaining active-path corridor. Invalid paths are cleared and one automatic replan is coalesced while stale planning results are prevented from overwriting newer state.

CURRENT LIMITS

Prototype, not a safety claim.

Not yet robot-calibrated

Current slope and step thresholds are software bootstrap values. Physical experiments still need to establish reliable step-up/down, forward-slope, cross-slope, and support limits for RUBI.

Global planning scope

The current terrain planner outputs a global path. Dynamic-obstacle stopping and local safety remain separate controller/local-planning responsibilities.
