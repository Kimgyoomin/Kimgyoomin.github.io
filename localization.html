LOCALIZATION

Pre-built Map Localization.

I modified the GenZ-ICP SLAM codebase into a pre-built-map localization module for our legged robot. Instead of presenting GenZ-ICP as my own SLAM algorithm, this project focuses on adapting an existing research implementation for scan-to-map localization, ROS2 frame semantics, timestamp handling, and real-robot use.

WHAT I CHANGED

From a SLAM codebase to a localization module.

Pre-built Map Localization

A previously generated point-cloud map is loaded as the global reference. Incoming LiDAR scans are matched against that fixed map so the module estimates the robot pose without rebuilding the map online.

  • Pre-built PCD map as the global reference
  • Scan-to-map ICP localization path
  • Pose output for the navigation stack

ROS2 / TF Integration

The original pipeline was reorganized around the frame relationships required by the robot navigation system. The work included odometry semantics, map correction, output frame IDs, and transform publication.

  • map → camera_init global correction
  • camera_init → livox_frame odometry path
  • Nav2-compatible transform chain

Timestamp Policy

Localization outputs, odometry, debug clouds, and TF must share a coherent time source. I added timestamp handling so live sensor operation and recorded-data experiments can be debugged consistently.

  • Sensor-stamp / runtime-stamp policy
  • Timestamp-aware TF lookup and publication
  • Consistent pose, odometry, and visualization timing

Real-Robot Evaluation

The module was tested on the legged robot in an indoor environment and visualized against the pre-built map in RViz. The experiment also exposed practical limitations of LiDAR-only scan matching under vibration, motion distortion, and repeated geometry.

LOCALIZATION STACK

GenZ-ICP was one localization path, not the whole story.

GenZ-ICP Adaptation

Used as the pre-built-map scan-matching research path. Its value in this portfolio is the code-level conversion from the original SLAM-oriented implementation into a localization component and the real-robot integration work around it.

FAST-LIO Integration

LiDAR-inertial odometry is also integrated as a practical navigation backbone candidate. My work here is system integration—frames, TF connectivity, timestamps, sensor mounting conventions, and stable odometry delivery to Nav2—not authorship of FAST-LIO itself.

ENGINEERING FOCUS

Localization is useful only when the rest of the robot can consume it.

Frame Semantics

Keeping map, odometry, moving-body, base, and LiDAR frames explicit and consistent across localization and navigation.

System Reproducibility

Separating live and rosbag time sources, validating TF age, and keeping the localization outputs reproducible enough to diagnose Nav2 integration failures.
