IMPLEMENTATION DETAILS

The front page says Navigation. The details explain how.

Global Planning

A custom ROS2/Nav2 global-planner path generates collision-aware routes on the navigation map. The implementation includes 8-connected search, cost penalties, corner-cut prevention, path reconstruction, smoothing, and heading generation.

  • Custom A* plugin
  • Costmap-aware route generation
  • nav_msgs/Path output

Path Following

The navigation stack converts the planned path into robot velocity commands through a path-following controller. The initial target is stable forward/yaw motion on the real platform.

  • Regulated Pure Pursuit
  • /cmd_vel generation
  • Goal / progress checking

Robot Interface

ROS velocity commands are bridged into the robot's LCM command channel and passed to the existing low-level locomotion controller. My work here is the navigation-side command interface and its safety/coordinate handling, not the locomotion policy itself.

  • ROS2 → LCM bridge
  • Deadman timeout
  • Velocity saturation / sign policy

Safety & Integration

Manual joystick control and autonomous navigation are separated because both can publish to the same low-level command channel. TF, footprint, inflation, timestamp consistency, and command ownership are treated as system-level safety conditions.
